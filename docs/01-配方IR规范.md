# 配方 IR 规范 v1

Recipe IR（Intermediate Representation）是本项目的架构基石。配方以结构化 JSON 存储，**动画是 IR 的纯函数投影**，没有任何一步需要人工逐配方编排。

决策背景见 `00-决策记录.md` ADR-002、ADR-009、ADR-014。

> **本文档中所有物理参数（孔隙率、稀释率、密度、粘度）均为初始估值，需在动画原型阶段实测调整。** 参数集中在 `packages/recipe-ir/src/physics.ts`，不许散落在渲染代码里。

---

## 1. 设计原则

| 原则 | 含义 | 为什么 |
| --- | --- | --- |
| **闭集枚举** | 动作、原料、杯型、冰型、单位全是有限枚举 | 动画能自动生成的前提；v2 让模型产出 IR 的前提 |
| **只引 ID，不内联样式** | 配方里只有 `ingredientId`，颜色/气泡/图标挂在原料表 | 改一次全站生效；配方不会因为样式调整而失效 |
| **纯函数投影** | `IR → Timeline` 无副作用、无 IO、无随机 | 可测试、可在任意端跑、可服务端预编译 |
| **粒子是时间的纯函数** | 气泡/烟雾/火焰由固定 seed + `t` 确定性算出 | **否则 seek 会不一致**，拖时间轴会跳变 |
| **关键帧稀疏 + 声明式插值** | Timeline 存区间端点，渲染器插值 | seek 到任意时刻是 O(1)，不需重放历史 |

## 2. 顶层结构

```jsonc
{
  "schemaVersion": 1,
  "glass": "coupe",              // 杯型 ID，见 §6
  "method": "shaken",            // 手法标记，用于筛选与展示，不驱动动画
  "servings": 1,

  "ingredients": [
    { "slot": "i1", "ingredientId": "rum-white",    "amount": 60, "unit": "ml",   "role": "base" },
    { "slot": "i2", "ingredientId": "lime-juice",   "amount": 25, "unit": "ml",   "role": "souring" },
    { "slot": "i3", "ingredientId": "simple-syrup", "amount": 15, "unit": "ml",   "role": "sweetener" }
  ],

  "steps": [
    { "id": "s1", "action": "ADD",     "target": "shaker", "items": ["i1","i2","i3"] },
    { "id": "s2", "action": "ICE",     "target": "shaker", "iceType": "cube", "fill": 0.8 },
    { "id": "s3", "action": "SHAKE",   "target": "shaker", "durationSec": 12, "intensity": "hard" },
    { "id": "s4", "action": "STRAIN",  "from": "shaker", "to": "glass", "strainer": "hawthorne" },
    { "id": "s5", "action": "GARNISH", "target": "glass", "garnishId": "lime-wheel", "position": "rim" }
  ]
}
```

`method` 枚举（**仅作标记与筛选，不参与动画编译**——动画完全由 `steps` 决定）：
`shaken | stirred | built | blended | thrown | swizzled | rolled | layered`

## 3. 原料条目（IngredientRef）

```ts
interface IngredientRef {
  slot: string          // 'i1'，本配方内唯一，供 steps 引用
  ingredientId: string  // 指向 ingredients 表
  amount?: number       // 是否必填取决于 unit，见下
  unit: Unit
  role: Role
  note?: string         // 「自制」「过桶」等作者补充，展示用
  optional?: boolean    // 可选原料，动画中虚化表现
}
```

### 3.1 Unit 与 amount 的约束（discriminated union）

**这层约束必须写进 zod schema。** 不写的话，v2 让模型生成 IR 时一定会吐出 `{ unit: "top_up", amount: 100 }`。

| 分组 | 单位 | `amount` | `amountMl` 派生 | 液面贡献 |
| --- | --- | --- | --- | --- |
| **体积** | `ml` `cl` `oz` | **必填，正数** | 精确换算 | 全额 |
| **勺量** | `barspoon` `tsp` | 必填，正数 | × 5 ml | 全额 |
| **准体积** | `dash` | 必填，正数 | × 0.6 ml | **忽略，只贡献色调** |
| | `drop` | 必填，正数 | × 0.05 ml | 忽略 |
| **计数** | `piece` `leaf` `wedge` `slice` | **必填，正整数** | `null` | 固体，占体积不算液体 |
| **无量** | `top_up` | **禁止出现** | 编译期计算 | 填至杯容量 |
| | `rim` | 禁止出现 | `null` | 无 |
| | `to_taste` | 禁止出现 | `null` | 忽略 |

换算常数（`packages/recipe-ir/src/units.ts`）：

```
1 oz = 29.5735 ml        1 cl = 10 ml
1 barspoon = 5 ml        1 tsp = 5 ml
1 dash = 0.6 ml          1 drop = 0.05 ml
```

`amountMl` **不存进 IR**，是读取时派生的。IR 里只有作者输入的原始值（ADR-014：`amount + unit` 是真相源）。`recipe_ingredients` 投影表会存 `amount_ml` 供 SQL 筛选。

### 3.2 Role 枚举

同一原料在不同配方里角色不同（金酒在 Martini 是 `base`，在 Long Island 只是 `modifier` 之一），所以角色挂在配方-原料关系上，不挂在原料表上（ADR-009）。

```
base        基酒      骨架
modifier    修饰料    加香酒、利口酒、第二种烈酒
sweetener   甜味剂    糖浆、蜂蜜
souring     酸味剂    柑橘汁、酸溶液
bittering   苦味剂    苦精、苦味利口酒
lengthener  延长料    苏打、汤力、起泡酒
texture     质地料    蛋清、奶油、泡沫剂
rinse       涮杯料    苦艾酒涮杯
garnish     装饰      柑橘皮、樱桃、草本
ice         冰
```

## 4. 容器模型

动画编译器的核心是一个**容器状态机**。`reduce(steps)` 逐步演化容器状态，每步产出关键帧。

```ts
type ContainerId = "shaker" | "mixing_glass" | "glass" | "blender" | "secondary"
```

- `glass` 永远是成品杯（形状来自 `ir.glass`），也是动画的最终焦点
- `secondary` 用于 `ROLL` / `THROW` 这类双容器动作
- 容器**按需隐式创建**：第一次被 `target` 引用时出现在场景里，倒空后淡出

```ts
interface ContainerState {
  id: ContainerId
  vessel: VesselSpec             // 形状与容量
  layers: LiquidLayer[]          // 自下而上。未混合时多层，混合后合并为一层
  solids: Solid[]                // 冰块、捣压残渣、水果块
  foamMl: number                 // 泡沫层（蛋清 / 干摇产生）
  temperatureC: number           // 驱动结霜表现
  dilutionMl: number             // 冰融水，影响 ABV 与总体积
  rimming: RimSpec | null
  garnishes: PlacedGarnish[]
  smokeDensity: number           // 0..1
  aromaMist: number              // 0..1，喷雾残留
}

interface LiquidLayer {
  volumeMl: number
  color: OKLab                   // 混色结果，见 §7
  opacity: number
  density: number                // 加权平均，决定分层顺序
  carbonation: number            // 0..1，气泡发射率
  texture: "clear" | "cloudy" | "creamy" | "foam"
  particles: ParticleSpec[]      // 薄荷碎、咖啡渣、香料粉
  sourceSlots: string[]          // 溯源 —— UI 悬停原料可高亮"这层是它造成的"
}
```

`sourceSlots` 是白拿的交互：配方页悬停某个原料，播放器高亮它贡献的液层。

### 4.1 混合度（mixedness）

容器不是"混合"或"未混合"的二元状态，而是连续的 `mixedness: 0..1`：

| 动作 | 对 mixedness 的作用 |
| --- | --- |
| `ADD` | 密度差大 → 保持分层（mixedness 不变）；密度接近 → 轻微混合 |
| `FLOAT` | **强制不混合**，新层独立 |
| `STIR` | 缓慢升至 ~0.85（保留清澈感） |
| `SHAKE` | 快速升至 1.0（完全混合 + 起泡 + 变浑浊） |
| `BLEND` | 1.0 + 质地变雪泥 |
| `SWIZZLE` | ~0.9 + 杯壁结霜 |

`mixedness = 1` 时 `layers` 合并为单层（加权混色）；`< 1` 时按密度排序保留多层，层间边界按 `mixedness` 做渐变模糊。**这是"摇匀"和"分层"能用同一套代码表达的关键。**

## 5. 动作词表（21 个）

所有动作共有的可选字段：

```ts
{
  id: string            // 步骤 ID，本配方内唯一
  action: Action
  text?: { zh?: string; en?: string }   // 作者覆写文案；缺省时自动生成，见 §8
  durationSec?: number  // 真实操作时长，影响语义（稀释量等）
  note?: string         // 小贴士，展示用不参与动画
}
```

> **真实时长 ≠ 动画时长。** 12 秒的硬摇不该让用户看 12 秒。编译器按压缩曲线映射：`animMs = clamp(400 + 900·log₂(1 + durationSec), 400, 2600)`。全局可加 `speedScale` 让用户调播放速度。

### 5.1 准备类

#### `CHILL` 冰杯
```jsonc
{ "action": "CHILL", "target": "glass", "method": "ice_water" }
```
`method`: `ice_water | freezer`

语义：`temperatureC → -4`。动画：杯中注入冰水 → 杯壁由外向内结霜 → 倾倒清空。`freezer` 时直接淡入霜层，无倾倒。

#### `RIM` 杯口圈
```jsonc
{ "action": "RIM", "target": "glass", "material": "i7", "coverage": "half" }
```
`material`: slot 引用（`unit: "rim"` 的原料，如盐/糖/Tajín）
`coverage`: `full | half`

语义：`rimming = { materialSlot, coverage }`。动画：柠檬角沿杯口抹一圈 → 杯口倒扣蘸料盘 → 杯口出现颗粒边（`half` 只覆盖近侧半圈）。

#### `RINSE` 涮杯
```jsonc
{ "action": "RINSE", "target": "glass", "items": ["i5"], "discard": true }
```
语义：少量液体挂壁，`discard: true` 时倒掉多余但保留挂壁着色。Sazerac 的苦艾酒涮杯。动画：液体在杯中旋转爬壁 → 倾倒 → 杯壁残留淡色薄膜。

### 5.2 装填类

#### `ADD` 倒入
```jsonc
{ "action": "ADD", "target": "shaker", "items": ["i1","i2","i3"], "pour": "sequential" }
```
`pour`: `sequential`（默认，逐个倒）| `simultaneous`（并行，加快节奏）

语义：对每个 item，按 `amountMl` 增加液体；按密度决定是新建层还是并入现有层。`dash`/`drop` 不增加体积，只调色。

动画：瓶身/量酒器从上方倾斜 → 液流注入（流速由 `viz.viscosity` 决定）→ 液面按杯型剖面上升（§6.2）→ 落点涟漪。

#### `ICE` 加冰
```jsonc
{ "action": "ICE", "target": "shaker", "iceType": "cube", "fill": 0.8 }
```
`iceType`: `cube | large_cube | sphere | cracked | crushed | block | dry_ice`
`fill`: `0..1`，冰占容器的体积分数

语义（**冰的排水计算，ADR-014**）：

```
冰实体积       = capacityMl × fill × (1 − porosity)
可容液体上限   = capacityMl × (1 − fill × (1 − porosity))
```

| iceType | porosity（初始估值） | 说明 |
| --- | --- | --- |
| `cube` | 0.40 | 标准方冰随机堆积 |
| `large_cube` | 0.45 | 大方冰孔隙更大 |
| `sphere` | 0.48 | 单颗球冰 |
| `cracked` | 0.35 | 裂冰碎片填充 |
| `crushed` | 0.28 | 碎冰密实 |
| `block` | 0.50 | 冰柱/长条 |
| `dry_ice` | — | **不参与液面**，只产生烟雾 |

满杯方冰（`fill: 1.0`）可容液体 ≈ 容量 40%，与实际吧台经验相符。

动画：冰块逐个从上方落入（带弹跳）→ 液面按排水上升 → `crushed` 呈雪泥堆积、`sphere` 为单颗大球、`block` 为竖直长条。`dry_ice` 落入后开始持续冒白雾。

#### `MUDDLE` 捣压
```jsonc
{ "action": "MUDDLE", "target": "glass", "items": ["i4","i6"], "intensity": "gentle" }
```
`intensity`: `gentle`（草本，只释放香气不碎叶）| `firm`（水果，压出汁）

语义：目标 items 的固体转为 `particles`；`firm` 时按预设出汁率增加液体体积并调色。

动画：捣棒自上而下压 3~4 次（`gentle` 幅度小、`firm` 幅度大且带扭转）→ 固体逐次碎裂 → 颜色从固体处向外渗出扩散。

### 5.3 混合类

#### `SHAKE` 摇
```jsonc
{ "action": "SHAKE", "target": "shaker", "durationSec": 12, "intensity": "hard", "dryShake": false }
```
`intensity`: `gentle | standard | hard`
`dryShake`: `true` 时**无冰干摇**（起泡专用，蛋清配方的第一段）

语义：`mixedness → 1.0`；`texture → cloudy`；加冰摇产生稀释：

```
dilutionMl += liquidMl × dilutionRate
dilutionRate = { gentle: 0.15, standard: 0.20, hard: 0.25 } × min(1, durationSec / 12)
```

含 `texture` 角色原料（蛋清/泡沫剂）时 `foamMl` 上升；`dryShake: true` 时 `foamMl` 上升更多且不稀释。

动画：摇壶加盖 → 沿斜轴高频往复晃动（幅度与频率随 `intensity`）+ 运动模糊 → 内部液体混色 → 壶身结霜 → `dryShake` 时可见泡沫在壶内堆积。

#### `STIR` 搅拌
```jsonc
{ "action": "STIR", "target": "mixing_glass", "durationSec": 30, "revolutions": 40 }
```
语义：`mixedness → 0.85`（**保留清澈**，不变浑浊）；`dilutionMl += liquidMl × 0.12 × min(1, durationSec/30)`。

动画：吧勺沿杯壁螺旋旋转 → 液体形成缓慢涡旋 → 冰块随流转动 → 杯壁结霜。混色比 SHAKE 慢且温和。

#### `SWIZZLE` 搅棒搅打
```jsonc
{ "action": "SWIZZLE", "target": "glass", "durationSec": 8 }
```
语义：`mixedness → 0.9`；强制结霜（`temperatureC → -6`）；要求容器内有 `crushed` 冰。

动画：swizzle stick 插入后高速旋转 → 碎冰上下翻滚 → 杯壁由下向上迅速结霜（Tiki 招牌表现）。

#### `ROLL` 滚动
```jsonc
{ "action": "ROLL", "from": "shaker", "to": "secondary", "times": 3 }
```
语义：`mixedness → 0.75`，**极少起泡**（Bloody Mary 用，避免摇出泡沫破坏质地）。

动画：两容器间来回倾倒，液体拉出连续流线，往复 `times` 次。

#### `THROW` 抛接
```jsonc
{ "action": "THROW", "from": "mixing_glass", "to": "glass", "times": 4, "height": "high" }
```
> 全部转移型动作（`ROLL` `THROW` `STRAIN` `DUMP`）统一用 `from`/`to`；单容器动作统一用 `target`。
语义：`mixedness → 0.9` + 充气（`carbonation` 微升，希腊式抛接的招牌口感）。

动画：液体从高处经滤网拉成长弧线落入下方容器，往复 `times` 次，弧线高度随 `height`。

#### `BLEND` 搅打
```jsonc
{ "action": "BLEND", "target": "blender", "durationSec": 20, "speed": "high" }
```
语义：`mixedness → 1.0`；`texture → creamy`；固体冰转为雪泥（`solids` 清空，体积并入液层并大幅提高不透明度）。

动画：刀片旋转 → 内容物形成涡流 → 逐渐变成均匀雪泥质地 → 停止后表面留下旋涡纹。

### 5.4 转移类

#### `STRAIN` 滤出
```jsonc
{ "action": "STRAIN", "from": "shaker", "to": "glass", "strainer": "hawthorne", "double": true }
```
`strainer`: `hawthorne`（霍桑滤网）| `julep`（茱莉普滤网）| `fine`（细密滤网）| `none`
`double`: 双重过滤（hawthorne + fine 叠加）

语义：液体与 `dilutionMl` 转移到目标容器，`solids` **留在源容器**。`double: true` 或 `fine` 时 `particles` 也被滤掉（清澈度提升）。源容器随后淡出。

动画：源容器倾斜 → 滤网卡在口部挡住冰块 → 液流落入目标杯 → 目标杯液面上升 → `double` 时可见第二层细网。

#### `DUMP` 整杯倒入
```jsonc
{ "action": "DUMP", "from": "shaker", "to": "glass" }
```
语义：液体**连同 `solids`（冰）一起**转移。Tiki 常用，保留摇过的碎冰。

动画：连冰带液整体倾入，冰块随液体翻滚落入。

### 5.5 完成类

#### `TOP_UP` 补满
```jsonc
{ "action": "TOP_UP", "target": "glass", "items": ["i5"] }
```
语义（**ADR-014 的关键动作**）：items 的 `unit` 必须是 `top_up`，实际体积在**编译期**计算：

```
补入量 = 可容液体上限 − 当前液体 − dilutionMl − headroomMl
headroomMl 默认 5ml（留杯口余量，避免视觉上满到溢出）
```

动画：气泡饮料沿杯壁缓慢注入 → 大量气泡自底部持续上升 → 液面升至杯口下方 → 顶部形成细密泡沫环。

#### `FLOAT` 浮层
```jsonc
{ "action": "FLOAT", "target": "glass", "items": ["i8"], "technique": "over_spoon" }
```
`technique`: `over_spoon`（沿吧勺背面）| `gentle_pour`（缓慢贴壁）

语义：**强制新建独立层，不混合**（无论密度是否合理——作者的显式意图优先）。层间边界锐利。

动画：吧勺背面朝上贴近液面 → 液体沿勺背铺开 → 形成清晰分层，边界有细微折射高光。

#### `GARNISH` 装饰
```jsonc
{ "action": "GARNISH", "target": "glass", "garnishId": "lemon-peel",
  "position": "rim", "prep": "expressed", "discard": false }
```
`position`: `rim`（挂杯口）| `in_glass`（投入杯中）| `float`（漂浮液面）| `skewer`（签串）| `side`（杯旁）
`prep`: `twist`（皮卷）| `wheel`（圆片）| `wedge`（角）| `flag`（旗）| `dehydrated`（脱水片）| `expressed`（挤皮油）| `slapped`（拍打草本）| `none`
`discard`: `prep: "expressed"` 时是否挤完丢弃

语义：追加 `PlacedGarnish`；`expressed` 时 `aromaMist` 上升。可用 `garnishId` 直接引用原料表，也可用 `items` 引用本配方的 slot。

动画：装饰物从上方入场并落位；`expressed` 时橙皮对着杯口一挤，喷出细小油雾粒子；`slapped` 时薄荷在手掌上拍一下再放入。

#### `SPRITZ` 喷雾
```jsonc
{ "action": "SPRITZ", "target": "glass", "items": ["i9"], "sprays": 2 }
```
语义：`aromaMist` 上升，不增加可感体积。

动画：喷雾器从上方喷出 `sprays` 次雾状粒子，粒子缓慢飘落至液面后消散。

#### `FLAME` 火烧
```jsonc
{ "action": "FLAME", "target": "glass", "subject": "garnish", "durationSec": 3 }
```
`subject`: `garnish`（烧装饰物）| `surface`（燎液面）| `peel_oil`（喷皮油过火）

语义：视觉效果，不改变液体状态。

动画：火焰粒子升腾；`peel_oil` 时橙皮油喷过火焰爆出橙色火星雨（招牌表现）。

#### `SMOKE` 烟熏
```jsonc
{ "action": "SMOKE", "target": "glass", "method": "smoking_gun", "cover": true, "durationSec": 10 }
```
`method`: `smoking_gun`（烟枪）| `torched_wood`（烧木板）| `dry_ice`（干冰）
`cover`: 是否加盖聚烟

语义：`smokeDensity → 0.8`，之后随时间指数衰减。

动画：烟雾粒子注入 → `cover: true` 时在杯内聚集翻滚，揭盖瞬间大量白烟溢出并沿杯壁下沉（重烟效果）。

#### `WAIT` 静置
```jsonc
{ "action": "WAIT", "target": "glass", "durationSec": 30, "reason": "settle" }
```
`reason`: `settle`（沉降分层）| `bloom`（泡沫成型）| `infuse`（浸泡出味）

语义：按 `reason` 演化——`settle` 让密度差导致的分层更清晰；`bloom` 让 `foamMl` 上浮形成致密泡沫冠（Ramos Gin Fizz）；`infuse` 逐渐调色。

动画：镜头静止，液体内部缓慢变化（分层边界收紧 / 泡沫上浮 / 颜色渗透），配一个时间流逝指示。

### 5.6 动作速查

| 分组 | 动作 |
| --- | --- |
| 准备 | `CHILL` `RIM` `RINSE` |
| 装填 | `ADD` `ICE` `MUDDLE` |
| 混合 | `SHAKE` `STIR` `SWIZZLE` `ROLL` `THROW` `BLEND` |
| 转移 | `STRAIN` `DUMP` |
| 完成 | `TOP_UP` `FLOAT` `GARNISH` `SPRITZ` `FLAME` `SMOKE` `WAIT` |

**故意合并进参数、不单列为动作的**（避免词表膨胀）：

| 常见说法 | 表达方式 |
| --- | --- |
| 干摇 dry shake | `SHAKE` + `dryShake: true` |
| 双重过滤 double strain | `STRAIN` + `double: true` |
| 细滤 fine strain | `STRAIN` + `strainer: "fine"` |
| 直调建杯 build | `ADD` 到 `target: "glass"` |
| 挤皮油 express | `GARNISH` + `prep: "expressed"` |
| 拍打薄荷 slap | `GARNISH` + `prep: "slapped"` |

## 6. 杯型与容器形状

### 6.1 剖面模型

```jsonc
{
  "id": "coupe",
  "nameZh": "碟形杯", "nameEn": "Coupe",
  "capacityMl": 180,
  "shape": {
    "profile": [                       // 内腔剖面，归一化坐标
      { "y": 0.00, "r": 0.12 },        // y=0 杯底，y=1 杯口
      { "y": 0.10, "r": 0.38 },
      { "y": 0.45, "r": 0.49 },
      { "y": 1.00, "r": 0.50 }
    ],
    "outline": "M ...",                // SVG 路径，仅用于描边绘制
    "stem": { "height": 0.55, "width": 0.04 },
    "base": { "radius": 0.30 }
  }
}
```

`profile` 是**归一化**的（`y`、`r` 都在 0..1），决定形状的长宽比；`capacityMl` 决定绝对尺寸。编译器求缩放系数 `k` 使体积自洽：

```
k³ · π ∫₀¹ r(y)² dy = capacityMl
```

好处：画剖面的人不用关心绝对毫米数，只画形状；容量改了形状不变。

### 6.2 体积 ↔ 液面高度

**这是自动液面的物理基础。** 圆盘法积分（旋转体）：

```
V(h) = k³ · π ∫₀ʰ r(y)² dy
```

`V` 单调递增，反解 `h(V)` 用**预计算查找表 + 线性插值**（128 个采样点足够，比二分更快且无分支）。查找表在 `VesselSpec` 构造时算一次并缓存。

非圆柱杯型（coupe、martini）的体积对高度是强非线性的——**这正是不能用"液面高度 = 体积 / 容量"偷懒的原因**。Martini 杯装一半容量时，液面远低于杯高一半。

## 7. 原料视觉字段与混色

### 7.1 `ingredients.viz`

样式挂在原料表上，配方只引 ID（ADR-002）——改一次全站生效。

```jsonc
{
  "id": "blue-curacao",
  "nameZh": "蓝橙利口酒", "nameEn": "Blue Curaçao",
  "category": "liqueur", "subcategory": "orange",
  "abv": 24,
  "density": 1.09,                    // g/cm³，决定分层顺序
  "viz": {
    "color": "#1b6fd6",
    "opacity": 0.85,
    "carbonated": false,
    "viscosity": "low",               // low | medium | high —— 影响倒注流速
    "texture": "clear",               // clear | cloudy | creamy | foam
    "iconId": "bottle-liqueur",
    "particle": null,                 // 'mint-leaf' | 'coffee-bean' | 'cinnamon' | ...
    "foaming": 0                      // 0..1，起泡倾向（蛋清为 1）
  }
}
```

### 7.2 混色：两种操作，两个空间

**这一节在原型实现时被测试推翻过一次，务必看清区别：**

| 操作 | 用什么 | 为什么 |
| --- | --- | --- |
| 混合两种**液体** | `mixLiquids` —— 线性 RGB 透射率加权几何平均（减色） | 液体是吸收介质 |
| 颜色**过渡/渐变**、关键帧插值 | `lerpOklab` / `mixOklab`（OKLab） | 感知均匀，过渡不发灰 |

**液体混合不能用 OKLab 加权平均。** OKLab 是感知空间，黄与蓝在 b 轴上近乎相反，加权平均会互相抵消趋于中性——混出蓝灰（实测 `#87a6ba`）而不是绿。那是**光的加色混合**的正确行为，但液体是透光吸收的：蓝橙利口酒 + 橙汁在杯子里确实偏绿。

减色模型用 Beer-Lambert 降到三通道的近似：

```
log T_mix = Σ wᵢ·log Tᵢ / Σ wᵢ        （线性 RGB 透射率的加权几何平均）
```

**透射率需要一个压缩系数**（`TRANSMITTANCE_FLOOR = 0.02`），否则某通道为 0 的液体会让几何平均塌成黑色。关键：这必须是**可逆的压缩重映射**而不是钳制——

```
混合前：T → floor + (1 − floor)·T
混合后：T → (T − floor) / (1 − floor)
```

用钳制会连单一液体的颜色一起改掉（作者在库里设 `#1b6fd6`，渲染出来变成 `#276fd6`）。压缩加逆变换保证单一液体精确往返、多液体永不塌黑、且处处连续。

其余字段的合并规则：

```
opacity     = 按体积加权平均，再按 mixedness 微调（摇匀更不透明）
density     = 按体积加权平均
carbonation = 加权平均，SHAKE 后归零（摇散气泡）
texture     = 优先级取最"重"的：creamy > foam > cloudy > clear
particles   = 并集
```

`dash` / `drop` 的体积可忽略但**着色能力很强**（2 dash Angostura 能把整杯染成淡褐色），所以混色时用远大于其实际毫升数的等效权重：`TINT_WEIGHT_PER_DASH = 4`、`TINT_WEIGHT_PER_DROP = 0.8`。初始值凭观感设定，需实测调整。

`mixedness < 1` 时不混色，而是按 `density` 降序（重的在下）排列多层，层间用 `mixedness` 控制渐变带宽度。

### 7.3 密度分层

```
排序键 = density（大的在下）
```

`FLOAT` 动作**绕过密度排序**，强制按作者指定顺序叠层——作者的显式意图优先于物理。Tequila Sunrise 的 grenadine（密度 1.18）自然沉底，不需要 `FLOAT`；B-52 的三层必须用 `FLOAT` 显式声明。

### 7.4 ABV 估算

```
abv_est = Σ(amountMl_i × abv_i) / (totalLiquidMl + dilutionMl)
```

只计入 `amountMl` 与 `abv` 均非空的原料。`dash`/`drop` 的酒精量忽略（体量太小）。`dilutionMl` 来自冰融水——**不算稀释会显著高估**：Daiquiri 摇后稀释约 25%，不算的话 ABV 虚高四分之一。

`abv_est` 在保存时算好写入 `recipes.abv_est`，供筛选使用。展示时标注「约」。

## 9. 输出：Timeline

```ts
interface Timeline {
  totalMs: number
  steps: TimelineStep[]        // 与 IR steps 一一对应 —— 支撑「单步回看」
  finalSceneMs: number         // 成品定格时刻，用于截封面图（ADR-015）
}

interface TimelineStep {
  stepId: string
  startMs: number
  durationMs: number
  label: { zh: string; en: string }
  keyframes: Keyframe[]
}

interface Keyframe {
  tMs: number
  scene: Scene
  ease: "linear" | "easeIn" | "easeOut" | "easeInOut"   // 到下一帧的插值曲线
}

interface Scene {
  containers: RenderedContainer[]
  props: Prop[]                // 摇壶、吧勺、捣棒、滤网、喷雾器的位置与姿态
  effects: Effect[]            // 气泡/烟雾/火焰/油雾的参数化发射器
  focus: ContainerId           // 镜头焦点，驱动缩放与居中
}
```

### 9.1 两条必须遵守的规则

**① 关键帧是完整场景快照，不是增量。** 渲染器只需找到 `t` 所属区间、对两端插值即可绘制——**seek 是 O(1)，不需要重放历史**。这是"拖时间轴"和"单步回看"能工作的前提。代价是数据量略大，对 20 秒动画完全可接受。

**② 粒子必须是 `t` 的纯函数。** 气泡、烟雾、火焰、油雾**不进关键帧插值**，而是由 `Effect` 的参数化发射器 + 固定 seed，在渲染时按 `t` 确定性算出位置。

```ts
interface Effect {
  kind: "bubbles" | "smoke" | "flame" | "mist" | "frost"
  seed: number                 // 固定，保证可重现
  startMs: number; endMs: number
  rate: number                 // 发射率
  region: Region               // 发射区域（跟随液层）
  params: Record<string, number>
}
```

**如果粒子带状态，seek 回退时位置就会跳变**，拖时间轴的体验会立刻崩坏。这条纪律没有妥协空间。

### 9.2 编译入口

```ts
// packages/animator-core
export function compile(
  ir: RecipeIR,
  vocab: ResolvedVocab,        // 已解析的原料 viz / 杯型剖面 / 冰参数
  opts?: { speedScale?: number; fps?: number }
): Timeline
```

`compile` 是**纯函数**：无 IO、无随机、无 `Date.now()`、不 import 任何渲染 API。同一份输入在浏览器、Node、WebView 里必须产出逐字节相同的 Timeline。

**CI 需强制的依赖检查**：`packages/animator-core` 的依赖图里不允许出现 `dom`、`canvas`、`svg`、任何框架。这条纪律是 ADR-004/005 全部灵活性的唯一来源。

## 10. 校验规则

除 schema 结构校验外，`validateRecipeIR(ir, vocab)` 还需检查业务规则：

| 级别 | 规则 |
| --- | --- |
| **error** | `slot` 在本配方内唯一 |
| **error** | `steps[].items` / `material` 引用的 slot 必须存在 |
| **error** | 每个 `ingredients[]` 条目至少被一个 step 引用（孤立原料是笔误） |
| **error** | `unit` 与 `amount` 的组合符合 §3.1 |
| **error** | `STRAIN` / `DUMP` / `ROLL` / `THROW` 的 `from` 容器此前必须已被创建且有内容 |
| **error** | `TOP_UP` 的 items 必须是 `unit: "top_up"` |
| **error** | `RIM` 的 `material` 必须是 `unit: "rim"` |
| **error** | `ingredientId` / `glass` / `garnishId` 必须存在于词表 |
| **error** | 步骤序列必须以内容进入 `glass` 结束（不能把酒摇完留在摇壶里） |
| **warn** | 总液量（含稀释）超过 `glass.capacityMl` 可容上限 |
| **warn** | `SWIZZLE` 但容器内无 `crushed` 冰 |
| **warn** | `SHAKE` 含 `texture` 角色原料但无 `dryShake` 段（蛋清配方通常需要干摇） |
| **warn** | `FLOAT` 的原料密度小于其下层（物理上会自己浮起，可能不需要 FLOAT） |
| **warn** | `ADD` 到 `glass` 之后又 `STRAIN` 到 `glass`（重复目标，疑似笔误） |
| **warn** | `abv_est` 超过 40% 或低于 3%（疑似用量填错） |

**error 阻止发布，warn 只提示。** v2 的 AI 生成路径把这些 warn 一并回灌给模型做修复（ADR-008 的修复环）。

## 11. 版本演进

`schemaVersion` 从 1 起。IR 是核心资产（ADR-018 不可逆性排序第 2 位），必须配版本迁移器：

```
packages/recipe-ir/src/migrate/
  v1-to-v2.ts     纯函数 (irV1) => irV2
  index.ts        migrate(ir) 自动升到最新版
```

**读取时惰性迁移**：从库里取出旧版 IR 就地升级到最新版再用，不做全库批量重写（避免一次性迁移事故）。`recipe_revisions` 保留原始版本，永不覆盖。

**兼容性约定**：

- 向词表**增加**枚举值 → 不升版本（新值老客户端会遇到未知 ID，渲染器必须对未知值降级为通用表现而非崩溃）
- **删除或改变**枚举值语义 → 必须升版本 + 写迁移器
- 增加可选字段 → 不升版本
- 增加必填字段 / 改变字段含义 → 升版本

渲染器对未知枚举值的降级策略（**必须实现，否则老客户端会白屏**）：未知 `action` → 跳过并显示文案；未知 `ingredientId` → 灰色占位液体；未知 `glass` → 退化为 `rocks`。
